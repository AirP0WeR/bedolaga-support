# Локальная база знаний

Всё, что лежит в этом каталоге с расширением `.md`, целиком попадает в
системный промпт модели. Файлы читаются рекурсивно и в алфавитном порядке.

## Что сюда класть

Только то, чего нет во встроенном FAQ бота. Сам FAQ сервис забирает живьём
через API и заново перечитывает раз в 15 минут — дублировать его здесь не
нужно и вредно: два источника разъедутся.

Хорошие кандидаты:

- шаги диагностики, которые не хочется показывать всем в публичном FAQ
  («переподключить», «обновить подписку в приложении», «сменить локацию»);
- разбор частых поломок с признаками, по которым их отличают друг от друга;
- вычищенные пары «вопрос — ответ» из закрытых тикетов.

## Чего сюда не класть

- **Персональные данные.** Выгружая Q&A из тикетов, вычищайте имена, почты,
  номера, суммы и разовые договорённости с конкретным клиентом. Модель
  перескажет клиенту то, что здесь написано.
- **Секреты**: токены, ссылки на подписки, доступы к панели.
- **Обещания**, которых сервис не выполняет: сроки, компенсации, гарантии.
  Денежные темы всё равно уходят человеку, но выдуманное обещание в базе
  просочится в ответ на соседний вопрос.

## Как писать

Один файл — одна тема. Внутри — конкретные шаги вместо рассуждений: модель
пересказывает базу, а не выдумывает поверх неё. Формулировки в духе «если
клиент говорит X — проверьте Y, затем Z» работают заметно лучше описательных.

Каталог монтируется в контейнер томом, поэтому правки подхватываются
перезапуском сервиса, без пересборки образа. В публичном репозитории имеет
смысл держать только этот файл, а содержательные гайды — рядом с деплоем.
