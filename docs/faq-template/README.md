# FAQ бота: формат и темы

Встроенный FAQ бедолаги — половина базы знаний сервиса: `app/kb.py` тянет его
через `GET /pages/faq` и перечитывает раз в 15 минут. Пустой FAQ означает, что
модель отвечает по одним внутренним заметкам, а клиент не может решить
типовой вопрос сам.

Тексты FAQ — контент вашего сервиса, и в этом репозитории их нет. Держите их
в своём приватном репозитории или рядом с деплоем и заливайте скриптом:

```
python scripts/faq_lint.py   --dir ~/faq          # проверить тексты
python scripts/faq_upload.py --dir ~/faq --dry-run
python scripts/faq_upload.py --dir ~/faq
python scripts/faq_upload.py --dir ~/faq --enable
```

FAQ правят и в админке, поэтому проверять стоит не только исходники, но и то,
что реально лежит в боте:

```
python scripts/faq_lint.py --live
```

Если API бота доступен только изнутри docker-сети, положите скрипты рядом с
деплоем и гоняйте в контейнере сервиса — там уже есть и адрес API, и токен, и
`ALLOWED_DOMAINS`:

```
docker cp tools/faq_lint.py <контейнер>:/srv/faq_lint.py
docker exec -w /srv <контейнер> python faq_lint.py --live
```

## Раскладка каталога

```
faq/
└── ru/
    ├── 01-s-chego-nachat.md
    ├── 02-kakoe-prilozhenie.md
    └── ...
```

Подкаталог — язык страницы (`--lang`, по умолчанию `ru`). Номер в начале имени
файла задаёт порядок страниц в боте.

## Формат файла

Первая строка — `# Заголовок`, он же название кнопки в боте. Дальше контент:

```markdown
# 🚀 С чего начать

Короткий вводный абзац.

<b>Подзаголовок</b>

1. Первый шаг.
2. Второй шаг.
```

Правила, которые проверяет скрипт:

- **Только Telegram-теги**: `<b> <i> <u> <s> <a> <code> <pre> <blockquote>
  <tg-spoiler>`. Бот шлёт FAQ обычным сообщением с `parse_mode=HTML`, поэтому
  `<p>`, `<ul>`, `<h2>`, `<img>` не просто игнорируются — Telegram отвергает
  всё сообщение целиком.
- **До 3500 символов на страницу** (`FaqService.MAX_PAGE_LENGTH`). Длиннее бот
  порежет на подстраницы с пагинацией: не ошибка, но разрыв посреди списка
  читается плохо.

Подзаголовки — `<b>…</b>` отдельной строкой, списки — строки с `- ` или `1. `.
Кабинет разворачивает такой текст в абзацы и списки сам.

## О чём писать

Проверенный набор тем — по одной странице на каждую:

1. **С чего начать** — три шага до работающего VPN, пробный период, где
   личный кабинет, чем отличаются способы входа.
2. **Какое приложение установить** — какой клиент под какую платформу и зачем
   он вообще нужен.
3. **Как добавить подписку в приложение** — обычный путь, ручное добавление по
   ссылке, что делать, если кнопка не сработала.
4. **Устройства** — где смотреть лимит, как подключить второе, как освободить
   место.
5. **Тарифы и подписка** — где смотреть и как сменить, продление, лимит
   трафика.
6. **Оплата** — способы, автоплатёж, «оплатил, а подписки нет», «деньги
   списались, баланс пуст».
7. **Не работает VPN** — чек-лист самопомощи и куда смотреть статус серверов.
8. **Реферальная программа** — когда начисляется бонус и когда нет.
9. **Как написать в поддержку** — что приложить к обращению.

## Чего избегать

- **Конкретных чисел**, которые живут в интерфейсе: цен, длительности пробного
  периода, лимитов устройств, сумм бонусов. Тарифы меняются, FAQ — нет.
  Отсылайте к разделу, где число показано.
- **Ссылок на домены вне `ALLOWED_DOMAINS`.** Пост-фильтр (`app/guard.py`)
  режет ответ модели с чужим доменом. Если ссылка на магазин приложений нужна
  в тексте — сначала добавьте домен в `ALLOWED_DOMAINS`, потом в FAQ.
- **Обещаний**: сроков ответа поддержки, возвратов, компенсаций, гарантий
  работы конкретных сайтов.
- **Названий кнопок по памяти.** Сверяйте с локалями своего бота: в них
  формулировки отличаются от того, что помнят операторы по старым тикетам.

## Что не в FAQ, а в `kb/`

FAQ публичный — его читают клиенты. Внутренние шаги диагностики, признаки
поломок и правила эскалации кладите в каталог `kb/`, он монтируется в
контейнер и в публичный доступ не попадает. См. `kb/README.md`.
