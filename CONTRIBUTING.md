# Как участвовать

Правки приветствуются. Ниже — то, что стоит знать до первого коммита, чтобы
ревью не свелось к переписке о формальностях.

## Окружение

Зависимости и venv — [uv](https://docs.astral.sh/uv/):

```bash
uv sync
uv run pytest -q
uv run ruff format . && uv run ruff check .
```

CI гоняет ровно это. `uv.lock` коммитится: если меняете зависимости, приложите
обновлённый лок (`uv lock`), иначе сборка упадёт на `--frozen`.

## Главное правило

Цена ошибки в этом проекте несимметрична. Не ответить клиенту — не страшно:
тикет подождёт человека, как было до сервиса. Ответить неверно, ответить
дважды или влезть в разговор с живым оператором — дорого и заметно всем.

Поэтому любая неоднозначность трактуется в пользу молчания, и правки,
двигающие поведение в другую сторону, требуют внятного обоснования.

## Где нужен тест

Два модуля решают, увидит ли клиент ответ:

- `app/gate.py` — можно ли трогать тикет,
- `app/llm.py::_sanitize` и `app/guard.py` — можно ли отправлять этот текст.

Правки в них принимаются **только с покейсовым тестом на новый случай**. Имена
тестов пишутся по-русски и читаются как формулировка правила — так по списку
тестов видно поведение целиком:

```python
def test_голосовое_перед_текстом_всё_равно_эскалирует():
```

Хороший тест на исправление бага падает на старом коде. Это стоит проверить
до отправки PR, а не после.

## Стиль

- `ruff format`, строка 120, одинарные кавычки — всё в `pyproject.toml`.
- Комментарии объясняют **почему**, а не что делает код. Если поведение
  выглядит странным, комментарий должен назвать причину: ограничение API
  бедолаги, защита от повторной отправки, осознанный перекос в молчание.
- Ссылки на код бота (`app/webapi/routes/tickets.py:213`) в комментариях
  приветствуются: поведение webapi нигде не задокументировано, и следующему
  человеку это сэкономит час.

## Что не принимается без обсуждения

- Хранение FAQ в репозитории. Он тянется живьём из админки бота осознанно:
  два источника разъедутся, и правка перестанет доезжать до модели.
- Ретраи на `POST /tickets/{id}/reply`. Сообщение коммитится в БД до ответа
  эндпоинта, поэтому повтор после обрыва отправит клиенту второй ответ.
- Любые записи в бота, кроме ответа в тикет и приоритета. Токен даёт полный
  доступ к webapi — сервис намеренно не пользуется ничем другим.

## Пулл-реквесты

Один PR — одно изменение. В описании: что было не так, что стало, и какой
тест это удерживает. Если правка меняет поведение по отношению к клиенту,
скажите об этом прямо в первой строке.
